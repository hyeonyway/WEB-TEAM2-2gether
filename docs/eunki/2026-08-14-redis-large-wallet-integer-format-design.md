# #484 Redis 큰 지갑 잔액 정수 직렬화 설계

## 배경

Redis 프로필의 지갑 충전, 입찰, 주문 정산 경로는 Lua에서 금액을 `tonumber()`로 계산한 뒤
문자열 연결이나 Redis 명령 인자로 전달한다. Lua가 큰 수를 지수 표기로 변환하면 Java의
`Long.parseLong()` 계약과 어긋난다. 이때 Redis Hash 갱신과 Stream 기록은 이미 끝났으므로
HTTP만 500으로 실패하고, 같은 멱등 키 재시도도 저장된 응답을 다시 파싱하다 실패할 수 있다.

## 목표

- Redis Hash, Stream, Lua 응답에 기록되는 모든 금액을 부호 있는 10진 정수 문자열로 통일한다.
- Lua의 IEEE-754 안전 정수 범위보다 충분히 낮은 서비스 정책 상한을 적용한다.
- 정책 초과 요청은 Redis 상태 변경 전에 도메인 예외 기반 HTTP 400으로 종료한다.
- 과거 멱등 키에 남아 있는 정확한 지수 표기 정수는 호환 파서로 재생할 수 있게 한다.
- 큰 잔액에서 충전, 환불, 입찰, 상회 입찰 해제, 즉시 낙찰, 주문 정산이 500 없이 동작하도록 회귀 테스트한다.

## 금액 정책

- 1회 지갑 충전·환불 최대 금액: `100_000_000_000L`(1,000억 원)
- 지갑 총 보유액 최대 금액: `1_000_000_000_000L`(1조 원)
- 경매 가격 및 주문 정산 금액 최대값: `1_000_000_000_000L`(1조 원)

모든 상한은 Java `long` 범위와 Lua의 연속 정수 정확도 한계인 `2^53 - 1`보다 충분히 낮다.
Java 진입 검증은 빠른 실패를 제공하고, Lua 검증은 동시 요청 사이에서도 총 보유액 상한을
원자적으로 보장한다.

## 구현

### 공통 숫자 계약

Lua에는 `integerString(value) = string.format("%.0f", value)` 형태의 변환을 둔다. 계산에 사용한
금액은 Redis Hash, Stream 필드, 멱등 결과, Lua 반환 문자열에 넣기 전에 이 변환을 거친다.
버전과 개수처럼 `HINCRBY`가 반환한 값도 Java 정수 파서와 동일한 계약을 사용한다.

`string.format`은 이미 손실된 정밀도를 복원하지 못하므로 출력 포맷만 고치지 않는다. 외부 요청과
Redis 현재 상태가 정책 상한을 넘지 않는지 쓰기 전에 검증한다.

### 대상 Lua 경로

- `wallet-transition.lua`: 충전·환불 금액, available/frozen balance, Stream, 멱등 응답
- `bid-accept.lua`: 입찰가, 신규/이전 입찰자 balance와 hold, 최근 입찰, timeline Stream, 응답
- `auction-close-request.lua`: 낙찰 금액과 낙찰자 지갑 차감 결과
- `order-wallet-transition.lua`: 판매자 정산 및 구매자 취소 환불 결과

시딩 스크립트는 Java가 만든 정수 문자열을 그대로 Redis에 전달하며 금액 산술을 하지 않으므로
새 숫자 포맷 계약의 회귀 테스트 대상에는 포함하되 불필요한 구조 변경은 하지 않는다.

### Java 경계

공통 금액 정책 클래스로 충전·환불·입찰 입력을 검증한다. Lua의 상한 거절 코드는 기존 도메인
예외 계층을 통해 HTTP 400으로 변환한다. Redis 응답의 신규 계약은 일반 10진 정수 문자열이다.

기존 멱등 결과에 남아 있을 수 있는 지수 표기는 `BigDecimal` 기반 exact 변환으로만 허용한다.
소수이거나 `long` 범위를 넘거나 정확한 정수가 아니면 정상 결과로 간주하지 않는다. 신규 Lua가
지수 표기를 생성하는 것을 허용하기 위한 범용 우회로로 사용하지 않는다.

## 원자성과 오류 처리

상한 검증은 모든 Redis 쓰기 전에 끝낸다. 검증 실패 시 Lua는 거절 코드만 반환하며 Hash, ZSET,
hold, Stream, 멱등 결과를 바꾸지 않는다. 승인 시에는 기존과 동일하게 상태 전이와 Stream XADD가
한 Lua 실행에 포함된다.

Java의 응답 변환이 예상하지 못한 값에 실패하더라도 원인을 식별할 수 있게 잘못된 숫자 계약을
명확한 예외로 감싼다. 이미 승인된 결과를 임의로 보상하거나 Redis에서 되돌리지는 않는다.

## 테스트

- 지갑 Lua: 큰 잔액 충전·환불, Hash/Stream/응답 정수 문자열, 멱등 재시도
- 입찰 Lua: 큰 잔액 입찰, 이전 최고 입찰자 hold 해제, 즉시 낙찰 차감, 정수 문자열
- 주문 Lua/마감 Lua: 큰 금액 정산·취소·낙찰 차감의 Hash/Stream/응답
- 정책 경계: 최대값 허용, 최대값 초과 시 400 및 Redis 무변경
- 호환 파서: 과거 지수 표기 정수 성공, 소수·범위 초과 실패
- 기존 Redis 통합 테스트와 관련 지갑/입찰 단위 테스트 전체 회귀
