# 로컬·S3 판매 이미지 업로드 테스트 계약

## 1. 목적

판매 이미지 업로드는 실행 환경에 따라 서로 다른 두 경로를 사용한다. 테스트가 개발자의
`.env.local` 값에 따라 달라지지 않도록, 각 테스트가 어떤 업로드 모드를 검증하는지
명시한다.

## 2. 현재 문제

로컬 개발 환경의 `.env.local`에는 `VITE_LOCAL_UPLOAD=true`가 설정돼 있다. Vitest가 이
값을 읽으면 S3 presigned URL 테스트도 로컬 반환 경로를 실행한다. 그 결과 S3 업로드
성공과 실패 변환 테스트가 모두 `local/<photoId>` 반환값 때문에 실패한다.

## 3. 결정

### 3.1 테스트 기본값

`sellApi.test.ts`의 각 테스트 시작 전 `VITE_LOCAL_UPLOAD=false`를 명시한다. S3 경로는
테스트 환경의 기본 경로가 된다.

### 3.2 로컬 경로

로컬 업로드 테스트에서만 `VITE_LOCAL_UPLOAD=true`로 덮어쓴다. 이 테스트는 presigned
URL 발급과 S3 PUT 요청이 발생하지 않고 `local/<photoId>` 토큰을 반환해야 한다.

### 3.3 S3 경로

다음 두 테스트는 기본값(`false`)을 사용한다.

- presigned URL 발급 뒤 이미지 PUT 요청을 보내고 업로드 토큰을 반환한다.
- S3 PUT 실패 응답을 공통 `HttpError`로 변환한다.

프로덕션 코드인 `sellApi.ts`의 환경 분기 자체는 이미 올바르므로 이번 범위에서 변경하지
않는다.

## 4. 구현·검증 순서

1. S3 테스트가 로컬 환경값에 의존하지 않는다는 실패 조건을 테스트로 먼저 만든다.
2. 테스트 초기화에서 S3 기본값을 명시한다.
3. `npm test -- --run src/api/sellApi.test.ts`를 실행한다.
4. `npm test -- --run`으로 프론트 전체 회귀를 확인한다.

## 5. 완료 기준

- `.env.local`의 `VITE_LOCAL_UPLOAD=true` 여부와 관계없이 S3 테스트 2개가 S3 경로를
  검증한다.
- 로컬 업로드 테스트는 로컬 토큰 반환과 네트워크 미호출을 검증한다.
- 프론트 전체 테스트가 통과한다.
