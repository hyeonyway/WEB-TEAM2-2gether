# 나의 대시보드 조회 설계

## 1. 목표와 범위

로그인 사용자가 참여 중인 경매와 최근 낙찰을 한 화면에서 조회한다. 이번 구현은 REST 조회와 화면 렌더링까지만 담당하며 SSE 연결과 경매 종료 처리는 포함하지 않는다.

경매 찜은 지원하지 않는다. 찜은 `wishlists.item_id`에 저장되는 카드 시세 도메인의 기능이며 카드 시세 목록과 상세에서만 노출한다.

## 2. 인증 경계

```http
GET /api/dashboard/participating-auctions
GET /api/dashboard/recent-wins
```

참여 중인 경매 API는 서버 정렬 조건을 받는다.

```http
GET /api/dashboard/participating-auctions?sort=ENDING_SOON
GET /api/dashboard/participating-auctions?sort=PRICE_HIGH
```

- `ENDING_SOON`: 종료 예정 시각 오름차순
- `PRICE_HIGH`: 현재 경매가 내림차순

최근 낙찰 API도 서버 정렬 조건을 받는다.

```http
GET /api/dashboard/recent-wins?sort=LATEST
GET /api/dashboard/recent-wins?sort=OLDEST
GET /api/dashboard/recent-wins?sort=PRICE_HIGH
```

- `LATEST`: 경매 종료 시각 내림차순
- `OLDEST`: 경매 종료 시각 오름차순
- `PRICE_HIGH`: 낙찰가 내림차순

Controller는 경로나 쿼리에서 사용자 ID를 받지 않고 `@CurrentUser Integer userId`만 사용한다. 따라서 클라이언트가 다른 사용자의 ID를 지정해 대시보드를 조회할 수 없다.

현재 실제 JWT 필터 통합 전이므로 `RequestCurrentUserProvider`가
`X-Debug-User-Id`를 직접 읽는다. 별도의 `TestAuthFilter`와 Spring 프로필은
사용하지 않는다. 이후 JWT 필터가 request의 `userId` attribute를 채우면 해당
값을 우선 사용하므로 대시보드 호출부는 변경되지 않는다.

프론트 로컬 디버깅에서는 테스트할 사용자 ID를 브라우저에 저장한다.

```js
localStorage.setItem('DEBUG_USER_ID', '1')
```

공통 HTTP 클라이언트는 `DEBUG_USER_ID`가 양의 정수일 때만
`X-Debug-User-Id`로 전달한다. 값이 없거나 잘못된 값이면 해당 헤더 없이
요청한다. JWT 저장·파싱·Bearer 헤더 연결은 실제 JWT 필터 통합 작업 전까지
사용하지 않는다.

## 3. 조회 기준

### 참여 중인 경매

1. `bids.user_id`가 인증 사용자와 같은 입찰을 생성 시각·ID 내림차순으로 조회한다.
2. 경매별 첫 입찰만 남겨 사용자의 최신 입찰 상태를 선택한다.
3. 경매 상태가 `OPEN`, `ENDING`인 항목만 반환한다.
4. 종료 예정 시각 오름차순으로 정렬한다.

### 최근 나의 낙찰

1. 같은 최신 입찰 집합에서 `BidStatus.WON`만 선택한다.
2. 요청한 정렬 조건에 따라 종료 시각 또는 낙찰가로 정렬한다.
3. 현재 종료 처리 로직이 `WON`을 만들지 않으면 빈 배열을 반환한다.

## 4. 응답 계약

두 API 모두 아래 경매 스냅샷 배열을 반환한다.

```json
[
  {
      "id": 12,
      "card": {
        "id": 101,
        "name": "피카츄",
        "psa_grade": "10",
        "language": "JP",
        "thumbnail_url": "pokemon-cards/card.webp"
      },
      "start_price": 100000,
      "current_price": 150000,
      "bid_increment": 1000,
      "bid_count": 3,
      "ends_at": "2026-07-30T12:00:00",
      "status": "OPEN",
      "version": 2,
      "my_bid_status": "LEADING",
      "my_bid_amount": 150000
  }
]
```

카드 메타데이터는 `card_metadata`, 대표 이미지는 경매의 첫 `images` 행을 사용한다. 경매 이미지가 없으면 카드 메타데이터 이미지를 사용한다.

## 5. SSE 확장 지점

`id`는 경매 이벤트 라우팅 키, `version`은 오래된 이벤트나 응답을 구분하는 기준으로 유지한다. 추후 SSE가 연결되면 다음 두 방식 모두 현재 응답 계약을 변경하지 않고 적용할 수 있다.

- 이벤트 payload의 경매 스냅샷으로 React Query 캐시 항목 교체
- 이벤트를 갱신 신호로 사용해 현재 탭의 대시보드 API 재조회

이번 구현에는 emitter, EventSource, 이벤트 리스너를 추가하지 않는다.
